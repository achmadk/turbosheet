## ADDED Requirements

### Requirement: Getting-started tutorial

The project SHALL include a getting-started tutorial that enables a new user to install TurboSheet, launch a browser, write a test, and run it within 5 minutes.

#### Scenario: Tutorial covers full happy path

- **WHEN** a new user follows the getting-started tutorial
- **THEN** they SHALL be able to: install via `npm install turbosheet`, launch a Chromium browser, navigate to a URL, interact with a page element, write and run a test with assertions, view test results

### Requirement: Comprehensive API reference

The documentation SHALL contain a complete API reference covering every public class, method, and configuration option, organized by module.

#### Scenario: API reference covers all exports

- **WHEN** a developer views the API reference
- **THEN** every public API exported from 'turbosheet' SHALL have a documented entry with: signature, parameter descriptions, return type, example usage, and notes on browser compatibility

#### Scenario: Configuration reference

- **WHEN** a developer views the configuration documentation
- **THEN** every option in tsheet.config.ts SHALL be documented with type, default value, description, and example

### Requirement: Migration guides

The project SHALL include comprehensive migration guides from Playwright, Cypress, and Puppeteer, with side-by-side API comparison tables and step-by-step instructions.

#### Scenario: Playwright migration guide

- **WHEN** a Playwright user views the migration guide
- **THEN** they SHALL see: API comparison table (Playwright → TurboSheet), common migration patterns, configuration differences, fixture system comparison, and a step-by-step migration checklist

#### Scenario: Cypress migration guide

- **WHEN** a Cypress user views the migration guide
- **THEN** they SHALL see: conceptual differences (command chains → async/await), API comparison table, custom command migration patterns, plugin migration guide

### Requirement: CI/CD integration with shipping workflow files

The project SHALL ship working CI/CD workflow files for GitHub Actions, GitLab CI, Jenkins, and CircleCI. These SHALL be generated by `tsheet init --ci <platform>` and also available as templates.

#### Scenario: GitHub Actions workflow generation

- **WHEN** `tsheet init --ci github` is executed
- **THEN** it SHALL create `.github/workflows/tsheet.yml` with: checkout, Node setup, dependency install, browser install, test execution, reporter output upload, and screenshot artifact upload

#### Scenario: CI templates use official Docker images

- **WHEN** a generated CI workflow is inspected
- **THEN** it SHALL reference official TurboSheet Docker images from GitHub Container Registry
- **AND** it SHALL include browser binary caching configuration

### Requirement: Shipping .github/ directory

The project SHALL include a `.github/` directory with reusable GitHub Actions workflows and issue templates.

#### Scenario: CI workflow ships with package

- **WHEN** the package is installed
- **THEN** `.github/workflows/test.yml` SHALL exist as source in the repository (not as a generated file only)
