## Context

Turbosheet is migrating from a basic E2E tool to a robust, enterprise-grade testing framework. We recently migrated to an `injected-script-engine` which standardizes actionability and provides a stealthy bridge between Rust and JS. However, our actionability engine lacks deep layout checks (scrolling, pointer-events), our network layer lacks easy mocking/HAR support, and we do not have a robust UI trace viewer or advanced assertions.

## Goals / Non-Goals

**Goals:**

- Eliminate flake by auto-scrolling and ensuring elements are stably attached and receiving pointer events.
- Support piercing open Shadow DOMs natively via a custom selector engine.
- Build a GUI Trace Viewer to replay traces generated by `TraceRecorder`.
- Provide high-level ergonomic APIs for network mocking and HAR playback.
- Implement soft assertions and robust retries.

**Non-Goals:**

- Changing the underlying browser drivers (we stick to CDP for Chromium, WebDriver BiDi for Firefox, and WebDriver for WebKit).
- Re-writing the existing `injected-script-engine` from scratch (we will extend it).

## Decisions

- **Shadow DOM Piercing**: We will implement a custom selector syntax parser in JS (e.g., `css=`, `text=`) inside `injected-core.ts` that recursively queries `shadowRoot`s.
- **Trace Viewer UI**: Built as a separate Vite/React or Vite/Vue app that reads the JSON traces produced by Turbosheet. DOM Rehydration will happen by inserting the `html` string into an `<iframe>` and overlaying coordinates.
- **Network Mocking API**: We will enhance `src/page.rs` and `src/network/proxy.rs` to support declarative mocks (`page.route("**/*", mock_response)`). HAR playback will hook into `NetworkProxy` to match request signatures against the HAR file.
- **Web-First Assertions**: Extend `AssertionEngine` to support polling specific JS evaluation snippets with `setInterval`-like logic wrapped in Tokio `select!` loops.

## Risks / Trade-offs

- **[Risk] Complex Shadow DOM querying is slow** → Mitigation: Optimize the custom selector engine to avoid deep recursive traversal when not needed, and cache parsed ASTs.
- **[Risk] Trace Viewer DOM Rehydration isn't perfect** → Mitigation: Use a robust freeze-dry approach that inline styles and disables scripts before capturing the `html`.
- **[Risk] Transparent HTTPS proxy doesn't support easy body mocking** → Mitigation: Implement a MitM approach for specifically mocked domains where we provide custom certificates for interception.
